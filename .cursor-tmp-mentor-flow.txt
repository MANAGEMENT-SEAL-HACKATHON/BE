0.1 Mục đích tài liệu

Đây là tài liệu ĐẦY ĐỦ duy nhất cho góc nhìn Mentor (Cố vấn) — đối ứng
với 4 file Coordinator (MF-01..06) và Student v1.1. Không phân chia 6
giai đoạn vì Mentor có chức năng ÍT HƠN Student và Coordinator — gộp

cứu.

0.2 Định nghĩa role MENTOR

  -----------------------------------------------------------------------
  [Định nghĩa CHẶT] Mentor là người CỐ VẤN cho đội thi trong vòng Sơ loại
  — KHÔNG phải Judge (chấm điểm), KHÔNG phải Coordinator (quản lý), KHÔNG
  phải Student (thi đấu). Mentor có user.role='MENTOR' và
  status='APPROVED' trong DB. Mỗi Mentor có thể được phân vào nhiều Track
  Sơ loại nhưng UNIQUE(mentor_id, track_id) — không trùng Track.

  -----------------------------------------------------------------------

3. FR — Đăng nhập & Hồ sơ cá nhân (FR-M-01..04)

3.1 FR-M-01 — Login (gồm cả tài khoản tạm 48h cho EXTERNAL)

  --------------------------------------------------------------------------
  Khía cạnh       Đặc tả
  --------------- ----------------------------------------------------------
  Mô tả           Mentor INTERNAL login thường (email FPT). Mentor EXTERNAL
                  nhận email với one-time link 48h (is_temp_account=TRUE) →
                  click → set mật khẩu lần đầu.

  API             POST /api/v1/auth/login { email, password }

  Pre-condition   users.role='MENTOR' AND users.status='APPROVED'
                  (Coordinator đã duyệt ở GĐ1 FR-05)

  Edge case       Tài khoản tạm hết 48h chưa active → 410
                  INVITATION_EXPIRED; Coordinator phải resend link
  --------------------------------------------------------------------------

  UI           Trang Hồ sơ hiển thị: tên, email, đơn vị (Chapter cho
               INTERNAL hoặc tổ chức cho EXTERNAL), is_dept_head (nếu có)

4.2 FR-M-06 — Xem đội được phân công (cấp độ Team)

  -----------------------------------------------------------------------
  Khía cạnh    Đặc tả
  ------------ ----------------------------------------------------------
  API          GET /api/v1/me/mentor-team-assignments?round_id=<sơ loại
               id>

  Response     Array of { team_id, team_name, leader_id, leader_name,
               leader_email, member_count, track_id, track_name,
               assigned_at }

  UI           Sau bốc thăm + Bước 7 GĐ2: Mentor thấy danh sách đội mình

  Tiền đề      (1) Coordinator đã chạy Bước 7 GĐ2; (2) UNIQUE(team_id,
               round_id) — 1 Mentor/đội/vòng

  Edge case    Đội bị Disband (status=REJECTED) sau Bước 7 →
               mentor_team_assignments tự CASCADE xóa (teams DELETE
               CASCADE)

5. FR — Theo dõi đội (FR-M-08..13) — chức năng chính

5.1 FR-M-08 — Xem chi tiết đội (read-only)

  -----------------------------------------------------------------------

  ------------ ----------------------------------------------------------
  API          GET /api/v1/teams/{team_id} (role=MENTOR)

  Response     { team_id, team_name, leader_id, leader_full_name,
               leader_email, chapter_id, chapter_name, status,
               member_count }

  BR-M-4       Mentor CHỈ xem được teams nằm trong
               mentor_assignments.track_id của mình HOẶC
               mentor_team_assignments.team_id của mình. Endpoint guard:

  Code guard   WHERE team_id IN (SELECT team_id FROM
               mentor_team_assignments WHERE mentor_id=:me) OR team_id IN
               (SELECT t.id FROM teams t JOIN team_round_tracks trt ON
               trt.team_id=t.id WHERE trt.track_id IN (SELECT track_id
               FROM mentor_assignments WHERE mentor_id=:me))

15.2 M-BUG-2 — Mentor act như Judge nhầm 2 vai trò trong UI

  -----------------------------------------------------------------------

  ----------- -----------------------------------------------------------
  Mức         Cao

  Sửa v1.0    Sidebar phân tách 2 mục riêng: 'Mentoring' (chỉ track/team
              được mentor) và 'Judging' (chỉ Track judge). Mỗi context
              không kế thừa permission của context kia. BR-M-10.

15.3 M-BUG-3 — Mentor không nhận MENTOR_TEAM_CHANGED khi đội rời

  -----------------------------------------------------------------------
  Khía cạnh   Nội dung
  ----------- -----------------------------------------------------------
  Mức         TB

  Triệu chứng Coordinator đổi Mentor M1 → M2 cho đội T1 (FR-13C-R). M2
              nhận MENTOR_TEAM_ASSIGNED nhưng M1 không nhận
              MENTOR_TEAM_REMOVED → M1 vẫn nghĩ đang mentor T1.

  Sửa v1.0    Worker FR-13C-R phải gửi MENTOR_TEAM_REMOVED đến M1 (đã bỏ
              phụ trách) + MENTOR_TEAM_ASSIGNED đến M2. Cả 2 notif cùng
              transaction.
  -----------------------------------------------------------------------

15.4 M-BUG-4 — Mentor EXTERNAL sau 48h vẫn login được do soft check

  -----------------------------------------------------------------------
  Khía cạnh   Nội dung
  ----------- -----------------------------------------------------------
  Mức         TB

  Triệu chứng Nếu app chỉ check is_temp_account=TRUE → Mentor đã active
              rồi vẫn dùng được. Nhưng nếu link 48h hết mà user CHƯA
              active → vẫn login → bypass.

  Sửa v1.0    Login flow: nếu is_temp_account=TRUE → KIỂM TRA
              temp_account_expires_at vs NOW(). Nếu expired → 410
              INVITATION_EXPIRED. Khi user set password lần đầu → set
              is_temp_account=FALSE.

15.6 M-BUG-6 — Mentor xem điểm trước scoring_locked qua endpoint khác

  -----------------------------------------------------------------------
  Khía cạnh   Nội dung
  ----------- -----------------------------------------------------------
  Mức         TB

  Triệu chứng GET /teams/{id}/scores có guard ROUND_NOT_LOCKED. Nhưng
              v_round_leaderboard cũng query scores → nếu Mentor có quyền
              GET /hackathons/{id}/preliminary-leaderboard → bypass.

  Sửa v1.0    Tất cả endpoints liên quan điểm CHO MENTOR phải có guard
              scoring_locked=TRUE. v_round_leaderboard chỉ accessible khi
              locked.
