> 🚨 \[LỖI NGHIÊM TRỌNG\] Criteria weight là cross-record validation:

  per-row          {TECHNICAL,SOFT_SKILL,PENALTY}; max_score \> 0;
                   name NOT NULL

  Validation       SUM(weight WHERE type != \'PENALTY\') ACROSS tất
  aggregate        cả criteria của track = 1.0. Validate khi: (1)
  (cross-record)   Coordinator bấm \"Confirm criteria set\" hoặc (2)

                   trước; ON DELETE SET NULL; không ảnh hưởng
                   validation

  Error            CRITERIA_WEIGHT_EXCEEDS_LIMIT (nếu thêm sẽ \>
                   1.0); CRITERIA_WEIGHT_NOT_COMPLETE (sum ≠ 1.0 khi
                   confirm)

**1. Phân tích gốc rễ --- Tại sao DELETE khó?**

**1.1 Vấn đề #1 --- FK Chain bị gián đoạn giữa chừng**

Đây là nguyên nhân phổ biến nhất. Chuỗi CASCADE bị cắt khi 1 bảng giữa
chain dùng RESTRICT thay vì CASCADE.

> \-- Ví dụ: muốn DELETE round_id=5 (chưa thi, không có đội)
>
> \-- Chuỗi cascade:
>
> DELETE rounds(5)
>
> → CASCADE DELETE tracks(round_id=5) \[tracks.round_id → rounds ON
> DELETE CASCADE ✓\]
>
> → CASCADE DELETE criteria(track_id) \[criteria.track_id → tracks ON
> DELETE CASCADE ✓\]
>
> → CASCADE DELETE scores(criterion_id)???
>
> \-- ❌ CHẶN! Nếu scores.criterion_id → criteria.id ON DELETE RESTRICT
>
> \-- Dù rounds không có đội thi nào, vẫn không DELETE được
>
> \-- nếu có bất kỳ score nào (kể cả data test) link vào criteria của
> track đó

**1.2 Vấn đề #2 --- App guard không chính xác**

> \-- Code hiện tại (sai):
>
> if (round.hasTracks()) → throw \"Cannot delete round with tracks\"
>
> \-- Vấn đề: tracks là CONFIG data, không phải COMPETITION data
>
> \-- Đội có thi hay chưa phụ thuộc vào team_round_participation, không
> phải tracks
>
> \-- Code đúng (v3.5):
>
> if (round.hasTeamParticipation()) → throw \"Cannot delete round with
> competition data\"
>
> \-- team_round_participation là ranh giới: CÓ = đã thi, KHÔNG CÓ = chỉ
> config

**3.2 Tại sao team_round_participation.round_id là RESTRICT?**

Đây là key design decision. Nếu team_round_participation.round_id →
rounds ON DELETE CASCADE, thì khi xóa round (dù round đã có đội thi),
toàn bộ participation records bị xóa → mất lịch sử competition. RESTRICT
đảm bảo: \"Muốn xóa round, phải đảm bảo không có đội nào đã tham gia.\"

> \-- RESTRICT trên team_round_participation.round_id là intentional:
>
> \-- 1. App check TRƯỚC: COUNT(team_round_participation WHERE
> round_id=:id) → 0?
>
> \-- 2. Nếu = 0 → không có đội nào thi → round chỉ là config → DELETE
> an toàn
>
> \-- 3. Nếu \> 0 → có đội đã thi → BLOCK với lỗi rõ ràng
>
> \-- 4. Nếu DB vẫn block dù = 0 → bug → check các FK khác

**10. Diagnostic Queries --- Tìm nguyên nhân khi DELETE fail**

> \-- Khi DELETE round thất bại, chạy query này để tìm offending FK:
>
> SELECT \'team_round_participation\' AS blocking_table, COUNT(\*) AS
> count
>
> FROM team_round_participation WHERE round_id = :round_id
>
> UNION ALL
>
> SELECT \'team_round_tracks\', COUNT(\*)
>
> FROM team_round_tracks trt JOIN tracks t ON t.id=trt.track_id
>
> WHERE t.round_id = :round_id
>
> UNION ALL
>
> SELECT \'submissions\', COUNT(\*)
>
> FROM submissions s JOIN tracks t ON t.id=s.track_id
>
> WHERE t.round_id = :round_id
>
> UNION ALL
>
> SELECT \'scores\', COUNT(\*)
>
> FROM scores sc JOIN criteria c ON c.id=sc.criterion_id
>
> JOIN tracks t ON t.id=c.track_id WHERE t.round_id = :round_id
>
> UNION ALL
>
> SELECT \'mentor_team_assignments\', COUNT(\*)
>
> FROM mentor_team_assignments WHERE round_id = :round_id;
>
> \-- Kết quả: bảng nào có count \> 0 = bảng đang chặn DELETE
>
> \-- → DELETE records đó trước (nếu là test data)
>
> \-- → Hoặc báo user không thể xóa vì đã có competition data
