0. Mục đích & Phạm vi tài liệu

0.1 Tại sao gộp 6 GĐ thành 1 file

Hệ thống có 2 vai trò chính: Coordinator (BTC) và Student (User thi
đấu). Tài liệu Coordinator-side đã tách 6 file theo 6 GĐ (MF-01..06) vì
BTC có ~40+ chức năng phức tạp. Student chỉ có ~25 chức năng, đơn giản
hơn, không cần phân nhỏ. Đa số chức năng Student đã được CHỈNH ĐỊNH ở
phía Coordinator (vd: lock scoring → Student chỉ chờ; bốc thăm Spring →
Student chỉ xem kết quả; chấm điểm → Judge); Student chủ yếu tương tác ở
GĐ2 (đội), GĐ3/GĐ5 (nộp bài), GĐ6 (xem kết quả).

5.1 FR-U-07 — Tạo đội

+-----------------------------------------------------------------------+
| POST /api/v1/hackathons/{hid}/teams { team_name }                     |
|                                                                       |
| @Transactional BEGIN;                                                 |
|                                                                       |
| -- Validate                                                           |
|                                                                       |
| IF NOT EXISTS hackathon_registrations(user, hackathon) → 422          |
| NOT_REGISTERED                                                        |
|                                                                       |
| IF EXISTS teams t WHERE t.hackathon_id=:hid AND t.leader_id=:uid →    |
| 409 ALREADY_HAS_TEAM                                                  |
|                                                                       |
| IF EXISTS team_members tm WHERE tm.user_id=:uid AND                   |
| tm.team.hackathon_id=:hid AND tm.status='ACCEPTED'                    |
|                                                                       |
| → 409 ALREADY_IN_TEAM                                                 |
|                                                                       |
| IF EXISTS teams WHERE name=:name AND hackathon_id=:hid → 409          |
| TEAM_NAME_EXISTS                                                      |
|                                                                       |
| -- Insert (status=PENDING; chuyển ACTIVE sau khi đủ 3-5 thành viên +  |
| Coordinator approve)                                                  |
|                                                                       |
| INSERT teams (hackathon_id, team_name, leader_id, chapter_id,         |
| status='PENDING')                                                     |
|                                                                       |
| VALUES (:hid, :name, :uid, (SELECT chapter_id FROM users WHERE        |
| id=:uid), 'PENDING');                                                 |
|                                                                       |
| INSERT team_members (team_id, user_id, role='LEADER',                 |
| status='ACCEPTED');                                                   |
|                                                                       |
| COMMIT;                                                               |
+-----------------------------------------------------------------------+

  -----------------------------------------------------------------------
  [Tự động leader_id = creator] Người tạo đội tự động là Leader. KHÔNG
  cho phép tạo đội rồi gán Leader khác — phải Transfer Leader sau
  (FR-U-12). chapter_id auto-derive từ users.chapter_id của Leader (GĐ2
  v3.5 quy định).

|                                                                       |

|                                                                       |
| INSERT team_members(team_id, user_id, role='MEMBER',                  |

5.3 FR-U-09 — Accept / Reject invite (Member)

+-----------------------------------------------------------------------+
| PATCH /api/v1/invitations/{id}/respond { action: 'ACCEPT' | 'REJECT'  |
| }                                                                     |
|                                                                       |
| IF tm.user_id ≠ current_user → 403 NOT_INVITEE                        |
|                                                                       |
| IF tm.status ≠ 'INVITED' → 409 ALREADY_RESPONDED                      |
